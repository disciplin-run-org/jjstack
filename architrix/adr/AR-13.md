# AR-13: /review-lean folds back into /review under its original name; the two-skill split retires

## Context

AR-3 (2026-09-09) rebuilt /review under explicit budgets after a recall-max rewrite failed to converge, landing at 293 lines. Patches across a dozen further review rounds grew it back to 740 by 2026-09-13, the same drift AR-3 was written to stop, just not yet triggering a second rebuild.

Jesper asked for that rebuild directly, framed as a car analogy: background PRs had produced a working prototype with patches on patches, and the ask was a production model - same handling, nothing welded on, nothing sawed off, fewer lines and better structure.

A rebuild reviewed by its own new logic cannot certify that logic (AR-3's own stated limitation), so the rebuild shipped under a new name, `/review-lean`, so the still-unmodified `/review` could review it - merged as PR #50 (717491d), approved by an independent session (Code-Review-consolidate-tm) after two rounds of mutation-proven fixes, satisfying done-done rung 4.

Before replacing `/review` outright, the two ran side by side on real web-checks pull requests, comparing verdicts commit-for-commit: unit 1 (#87) was noise-floor only, no diff traced to the rewrite; unit 2 (#88+#89) found `/review-lean` catching a real security P1 (unscrubbed report data reaching S3) that `/review` had marked "verified clean", while `/review-lean` itself under-rated one proven P1 to P2 on a fact neither skill's text resolves (is the target deployed); unit 3 (#82+#83+#84) was started and cancelled mid-run on the user's instruction, and was not re-run before this decision - the first two units already showed parity-or-better, and the swap is reversible by revert if a regression surfaces later.

Separately, while preparing this change, `architrix/adr/AR-3.md`'s on-disk `paths` list was found to include `skills/review-lean/SKILL.md`, an addition made after AR-3 was already accepted (its `updated` timestamp on disk read 2026-09-10, a day after acceptance) - architrix's own model treats an accepted decision's body, paths included, as immutable except via supersede, so that addition was an out-of-band edit the canonical record never held. AR-6, which also listed the same path, is not tracked in architrix's store at all (a disk-only ADR, per the visibility gap AR-5's consequences already documented).

## Decision

Fold `/review-lean` back into `/review` under its original name, retiring the two-skill split.

Delete the 740-line `skills/review/SKILL.md`; rename `skills/review-lean/SKILL.md` to `skills/review/SKILL.md` unchanged in substance. Update every reference tied to the now-retired `review-lean` identity: the skill's own frontmatter (name, version, trigger description, the `shadows: claude-code:/review -> /code-review` declaration `/review-lean` did not carry while it ran separately), its attribution line and status-check context in the body, `test/smoke.sh`'s single surviving `review_skill_contract` call and its line-budget/emdash/non-empty ratchet (now pointed at `skills/review/SKILL.md`, kept at the same 470-line ceiling - never raised to fit an addition), `two-stage-review/SKILL.md`'s cross-reference, `references/pr-comment-voice.md`'s sibling-skill example, and `README.md`'s skill table (one row, not two).

Correct `architrix/adr/AR-3.md`'s `paths` list back to what architrix's accepted record actually holds, undoing the out-of-band addition rather than carrying it forward into a second file. Correct AR-6's disk-only `paths` list the same way, since the file it named no longer exists either way.

## Consequences

Accepted. One skill file and one test contract again, at 464 lines against 740 before this change (293 at AR-3's original acceptance) - a second contraction of the same growth AR-3 named, not a new problem.

Accepted, and named rather than hidden. QA unit 3 (#82+#83+#84) was never re-run before this swap. The gap is real; it did not gate the decision because units 1 and 2 already showed `/review-lean` at parity-or-better against real pull requests, including one case where it caught a defect the old version missed, and the change is a straightforward git revert if a regression surfaces later.

Accepted. `/review-lean`'s own byline and status context (`Claude jjstack/skills/review-lean/SKILL.md`, `jjstack/review-lean`) stop appearing on new PR comments; a re-review of a pull request whose earlier round posted under that identity will not find it via the current skill's own-round detector, which reads the current skill's attribution prefix. No open pull request was reviewed under that byline at the time of this change.

Accepted, and worth stating plainly: AR-3's disk copy had drifted from its accepted canonical record for three days before this correction, undetected. Nothing else in this repository currently checks that a governing ADR's on-disk file matches what architrix holds; this decision does not add that check, it only performs the one correction it found.

Outstanding, inherited unchanged from AR-3: the seeded-defect baseline AR-3 deferred (a dozen real defects from this repo's own revert/hotfix history, both reviewer generations run blind, scored on true positives, false positives, misses, wall-clock and tokens) still does not exist. Until it does, nobody has measured whether either version of `/review` finds more real bugs than the 276-line version AR-3 replaced.
