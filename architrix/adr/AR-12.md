# AR-12: The review daemon's required model comes from --model, not a hardcoded vendor name

Written by hand, with `.last_id` moved to 12 in the same commit, for the same
reason as AR-10 and AR-11: architrix's workspace clone of this repo lists
only AR-1 to AR-4. This record narrows AR-11: it changes only the model
requirement and how the daemon decides it. Everything else AR-11 decided —
the trigger, who may make a request, the window's exit behavior, the clean-exit
read — stands unchanged and is not restated here.

## Context

AR-10 and AR-11 both wrote the model requirement as a literal: the daemon
"is started with `--model opus[1m]`" and a round is sent "only ... after a
handshake turn whose transcript line shows an Opus model." The check itself,
`is_opus(model)`, hardcoded the string `"claude-opus"`.

Two things followed from that:

- Moving the daemon's reviewer sessions to a different model meant an edit to
  the check function itself, not just to a flag — the `--model` and
  `--retry-model` options existed but the gate that validated them did not
  read them.
- A first attempt at this change (2026-09-11) renamed `is_opus` to
  `is_sonnet` and hardcoded `"claude-sonnet"` in its place — the same defect
  moved to a new vendor name, caught in review before it landed.

## Decision

The model family the daemon requires is derived from `cfg.model` at the
point of the check, never written as a literal in the gate:

- `model_family(flag)` reduces either spelling `--model`/`--retry-model`
  accepts — a short alias with an optional context-window suffix
  (`sonnet[1m]`) or a full model id (`claude-sonnet-5[1m]`) — to the prefix
  a transcript's model line must start with (`claude-sonnet`).
- `matches_family(model, family)` is the only check; it takes that derived
  prefix as an argument.
- The gate call is `matches_family(model, model_family(self.cfg.model))`. The
  warning and error messages name the derived family, not a hardcoded one, so
  they stay correct if `--model` changes.
- The defaults change: `--model` defaults to `sonnet[1m]`, `--retry-model` to
  `claude-sonnet-5[1m]`. Reviewer sessions now run on Sonnet unless overridden.
  Changing the required family going forward needs only a different
  `--model`/`--retry-model` pair, never a code edit.

## Consequences

- `bin/jjstack-review-daemon` review sessions run on Sonnet by default.
  Restarting the already-running daemon process is required to pick this up;
  a daemon started before this change keeps running on the old default until
  restarted.
- The retry model must be kept in the same family as `--model` by whoever
  sets both; the daemon does not cross-check them, since the retry is meant
  to get onto the same family through a more specific alias, not a different
  one.
- Every test and fixture that pinned a session's model to `claude-opus-5` so
  it would pass the gate (`Sessions.boot`'s default, and every test built on
  it) now pins `claude-sonnet-5` instead, to keep matching the new default
  family. The frozen transcript specimens under `test/fixtures/review-daemon/`
  are untouched: they exercise `latest_model()`'s parsing, which is
  model-agnostic, not the family gate.
