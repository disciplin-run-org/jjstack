# AR-10: Review sessions are opened by a local poller, one per pull request, and ended only through the session's own exit

Written by hand, with `.last_id` moved to 10 in the same commit. Architrix's
workspace clone of this repo lists only AR-1 to AR-4, on main and on this
branch, so `adr_create` would have handed out an id already committed here.

## Context

Rung 4 needs a session that did not write the code to review every pull
request. Until now a person started each one. They saw a request for
`ai-assistant-2026`, opened a terminal in `~/PycharmProjects/Code-Review`, and
ran `claude-tm --role=<repo>-pr<N>`. They typed `/review`, kept the session
open for the rounds after fixes, and typed `/save-and-exit` after the merge.
Several ran at once. Nothing on this machine watched GitHub, and nothing could
start a worker: the tubemail hub and Quartermaster only talk to workers that
already exist. `claude-tm` needs a real terminal.

Four facts shaped the choice:

- The reviewer is an outside collaborator on 42 `JesperJurcenoks` and 13
  `disciplin-run-org` repositories. It belongs to no org. Anyone on GitHub can
  add it as a reviewer and ask this machine's model for a review.
- A freshly started worker writes no model line until it takes a turn. The hub
  reports `idle` before Claude has finished starting. The sessions must run on
  Opus, and the user's default model has not always been Opus.
- All 14 of the reviewer's notification threads were unread, and 9 were review
  requests on pull requests already merged.
- Anyone can @-mention an account on a public repository, but only an account
  with write access can request its review. GitHub also moves a notification
  thread's update time on a merge or a comment, and leaves the reason
  unchanged.
- A later round in the same session knows what the previous round found. That
  is why sessions were kept open by hand.

## Decision

A deterministic Python poller, `bin/jjstack-review-daemon`, run in the
foreground from the reviewer directory, does the dispatch. No model is
involved in deciding what to open, when to send, or when to end.

- GitHub notifications for the reviewer are the trigger. The reasons that
  count are `review_requested` and `mention`, on pull requests, polled with
  `If-Modified-Since`. A search sweep catches what the feed misses. An owner
  allowlist is checked before anything else, and a request on a closed pull
  request is skipped at the door.
- A notification is only a hint, so the daemon confirms the request behind
  it. A review request must still name the reviewer on the pull request, or
  carry a `review_requested` event newer than the last round. A mention must
  come from an account with write access to the repository. GitHub already
  puts that gate on a review request. Without it, any account could mention
  the reviewer on a public repository and get a session that runs the pull
  request's own tooling.
- Each pull request gets one worker, `<dir>-<repo>-pr<N>-tm`, in its own
  terminal window. It is started with `--model opus[1m]` and a session id the
  daemon chooses and keeps. Later rounds go to that worker. A crash resumes
  that session id.
- A round is sent only to an online, idle worker, after a handshake turn whose
  transcript line shows an Opus model. A wrong model is exited and retried
  once with the full model id, and never reviewed.
- A session ends when its pull request is merged, is closed, or has been idle
  for seven days. The daemon sends `/save-and-exit`. It never uses `tm_stop`
  or a signal, which is AR-2 applied to sessions the daemon owns.
- State is one JSON ledger beside the reviewer's `.env`, written atomically.

## Consequences

- The manual loop goes away. The reviewer's GitHub identity still comes only
  from the reviewer directory's `.env`. The daemon refuses to start when a
  token in the environment could override it, and when the login is not the
  reviewer.
- Requests from outside the allowlist cost nothing: a local log line, no
  reply, no session. The same goes for a mention from an account without
  write access. Each mention costs one permission lookup per author.
- Each round costs one extra short turn, the handshake. Pick-up latency is
  bounded by the two-minute poll plus that turn.
- The daemon is a foreground process someone must start. It is not a
  service. Its sessions outlive it, and a restart picks them up from the
  ledger.
- It depends on the hub's REST roster and its `tm_send` tool, on `claude-tm`
  passing unknown flags through to `claude`, and on the transcript format
  Claude Code writes. The frozen specimens under `test/fixtures/review-daemon/`
  pin the roster and transcript shapes as observed on 2026-09-10. They cannot
  see an upstream change: the suite stays green while the real format moves,
  so re-recover them after a Claude Code or tubemail upgrade. The hub routing
  `/exit` to the manager's pty, and `claude-tm` passing flags through, have no
  specimen at all. The tests pin only what the daemon sends.
- The @-mention path has never fired for this account on GitHub, so it is
  tested only against a thread re-labelled from a real specimen.
