# AR-11: Review sessions open only on a review request, one per pull request, and end only through the session's own exit

Written by hand, with `.last_id` moved to 11 in the same commit, for the same
reason as AR-10: architrix's workspace clone of this repo lists only AR-1 to
AR-4. This record replaces AR-10 whole and restates everything in it that
still holds. Only the trigger changes.

## Context

AR-10 made two notification reasons a trigger: `review_requested` and
`mention`. It gated a mention by the author's write access, because anyone
can @-mention an account on a public repository, while only an account with
triage or write access can request a review.

That gate had to decide whose words a mention was, and each independent review
round found another shape where the answer was wrong:

- **#49, round 1 (P0).** A mention was accepted from anyone. A stranger's fork
  PR could open a skip-permissions Opus session that runs its own tooling.
  Gated by write access.
- **#51, round 1.** Reading raw markdown by hand lost a writer's mention after
  a CRLF code block, ran in quadratic time on a stranger's comment, and let a
  stray backtick swallow a mention. The daemon moved to GitHub's own rendering.
- **#51, round 2 (P1).** A writer who quote-replied a stranger's refused
  mention, to decline it, opened a session for the stranger. The gate vouched
  for the comment's author, and the quote was someone else's words. Quotes were
  excluded.
- **#51, round 3 (STOP).** The same thing, through a quoted `[!NOTE]` callout
  and a quoted footnote, neither of which renders as a quote. The finding count
  did not fall, and the review handed the design back to the owner.

The mention path had never fired live for this account. Review requests drove
every real round, and the done-done rules already require a re-request after
every push that answers findings.

## Decision

A review request is the only trigger. `TRIGGER_REASONS` is
`("review_requested",)`. A mention, from anyone, in any words, starts nothing,
and its notification is left unread like a comment. The owner chose this over
listing more quote containers, and over voiding any comment that quotes. The
reason: GitHub already authorises a review request, so the daemon needs no
permission check and no reading of what anyone wrote.

The rest of AR-10 stands unchanged:

- A deterministic Python poller, `bin/jjstack-review-daemon`, run in the
  foreground from the reviewer directory, does the dispatch. No model decides
  what to open, when to send, or when to end.
- GitHub notifications for the reviewer are polled with `If-Modified-Since`.
  A search for pending review requests catches what the feed misses. An owner
  allowlist is checked before anything else, and a request on a closed pull
  request is skipped at the door.
- A notification is only a hint. A review request on a pull request with no
  session counts only while GitHub still lists the reviewer in
  `requested_reviewers`. On a pull request that has a session, it needs a
  `review_requested` event newer than the last round.
- Each pull request gets one worker, `<dir>-<repo>-pr<N>-tm`, in its own
  terminal window. It is started with `--model opus[1m]` and a session id the
  daemon chooses and keeps. Later rounds go to that worker, and a crash
  resumes that session id.
- A round is sent only to an online, idle worker, after a handshake turn whose
  transcript line shows an Opus model. A wrong model is exited and retried
  once with the full model id, and never reviewed.
- A session ends when its pull request is merged, is closed, or has been idle
  for seven days. The daemon sends `/save-and-exit`. It never uses `tm_stop`
  or a signal, which is AR-2 applied to sessions the daemon owns.
- State is one JSON ledger beside the reviewer's `.env`, written atomically.

## Consequences

- Asking for a round means requesting, or re-requesting, a review on GitHub.
  Typing `@ai-assistant-2026` in a comment does nothing.
- No stranger can start a session on an allowlisted repository by any
  comment, and the daemon reads no comment text at all. The permission
  lookups, the mention scanner, the HTML rendering reads and their fixtures
  are gone. That is less code, and fewer things that depend on GitHub's
  markup.
- A writer who requests a review on a stranger's fork PR still runs that PR's
  tooling in a skip-permissions session. That was true of the manual process
  too, and it is a deliberate act by someone the repository trusts.
- The daemon depends on the hub's REST roster and its `tm_send` tool, on
  `claude-tm` passing unknown flags through to `claude`, and on the transcript
  format Claude Code writes. The frozen specimens pin the roster and
  transcript shapes as observed on 2026-09-10. They cannot see an upstream
  change, so re-recover them after a Claude Code or tubemail upgrade.
- If mentions are wanted again, they should never open a session. A writer's
  mention could, at most, send a question to the pull request's existing
  session.
