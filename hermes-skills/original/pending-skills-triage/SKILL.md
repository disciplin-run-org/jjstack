# Pending Skills Triage

Use when `/skills pending` has a large backlog. Apply the same 3-tier cascade
logic used for email classification: obvious accepts, obvious rejects, and
probation for anything where classification isn't yet clear.

## Scope

Two distinct triage modes:

1. **Hermes pending queue** — triage `/skills pending` backlog (3-tier: Accept / Probation / Reject). See below.
2. **External repo evaluation** — evaluate a GitHub skill repo for import (4-bucket: already-covered / infra-mismatch / standalone-candidate / defer). See `references/external-repo-triage.md`.

Load `references/external-repo-triage.md` when the user asks to review, import, or evaluate skills from an outside source (GitHub repo, community pack, another agent's skill library).

## Classification Criteria

**ACCEPT** — clear, durable value:
- Skill captures a non-obvious workflow actually used and proven in a session
- Documents a specific pitfall that caused real pain (e.g. IMAP scope requirement)
- Is the canonical/final version when multiple drafts exist
- Created via `origin=assistant_tool` (intentional) rather than `origin=background_review`

**REJECT** — clear no value:
- Superseded by a later, better version of the same skill (keep only the final)
- Accidental writes (e.g. edit action with trivial/placeholder content)
- Duplicate of something already in memory or another accepted skill
- Captures knowledge that's too environment-specific to be reusable

**PROBATION** — leave in pending, revisit later:
- Potentially useful but unclear if it will actually be needed again
- Overlaps with existing skills — wait to see if a gap emerges
- Multiple variants where the best one isn't clear yet

**Move from PROBATION → ACCEPT** when:
- You actually reach for that knowledge and it's not in memory or skills
- A new session starts cold and you wish you had it

**Move from PROBATION → REJECT** when:
- It's been sitting unused for a month
- The knowledge is now in memory or a better skill

## Triage Process

1. Read all pending items:
```python
from pathlib import Path
import json
pending_dir = Path.home() / ".hermes/pending/skills"
items = []
for f in sorted(pending_dir.glob("*.json")):
    data = json.loads(f.read_text())
    payload = data.get("payload", {})
    items.append({
        "id": f.stem,
        "action": data.get("action"),
        "summary": data.get("summary",""),
        "name": payload.get("name","?"),
        "created_at": data.get("created_at", 0),
        "origin": data.get("origin",""),
    })
items.sort(key=lambda x: x["created_at"])
for i, item in enumerate(items, 1):
    print(f"{i:2}. {item['id']} | {item['action']:<12} | {item['name']:<40} | {item['summary'][:60]}")
```

2. Classify into ACCEPT / REJECT / PROBATION lists (just sets of ID strings).

3. Execute programmatically (no UI required):
```python
import sys
sys.path.insert(0, '/data/hermes/hermes-agent')
from hermes_cli.write_approval_commands import _approve, _reject

# Reject first (removes noise before accepting)
for rid in REJECT:
    print(_reject("skills", [rid]))

# Then accept
for aid in ACCEPT:
    print(_approve("skills", [aid], memory_store=None))

# Probation items: leave in pending, do nothing
```

4. Verify remaining == probation count:
```python
import tools.write_approval as wa
remaining = wa.list_pending("skills")
print(f"Remaining: {len(remaining)}")
for r in remaining:
    print(f"  {r['id']}: {r.get('summary','')[:70]}")
```

## Key Rules

- **Reject accidental edits first** — an `action=edit` with trivial content
  will overwrite the real skill if approved. Check edit payloads carefully.
- **When multiple creates exist for the same skill name, keep only the latest**
  unless an earlier one has clearly better content.
- **`origin=assistant_tool`** = intentionally created during a task.
  **`origin=background_review`** = auto-generated by Hermes curator — more likely
  to be duplicates or lower quality.
- **Probation is not limbo** — it's a deliberate "let time decide" state.
  The pending queue survives `/clear` and session restarts.

## Probation Review Trigger

Run this at the start of any session where you notice the pending queue is large:
```
/skills pending
```
Then re-apply this skill to re-triage what's matured.
